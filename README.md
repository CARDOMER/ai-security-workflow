# AI Security Workflow

Локальный MVP для кейса банка «Центр-инвест» на Cyber Garden 2026. Кнопка запускает статический анализ учебного проекта Repair Desk. Таблица и выгружаемый UTF-8 JSON строятся из одного ответа FastAPI.

## Запуск на Windows

Откройте копию репозитория или распакуйте ZIP в отдельную папку на ноутбуке. Установите Python 3.12+ и Node.js 22.12+ с npm, добавив их в PATH. Откройте обычный Windows PowerShell в папке с этим README и проверьте `python --version`, `node --version` и `npm.cmd --version`. Учебный проект и эталон поставляются отдельно от репозитория. Если папка `test-data` отсутствует, установите Git и скачайте её:

```powershell
git -c core.autocrlf=false clone --depth 1 https://github.com/TBagirov/training.git test-data
```

В первом терминале создайте окружение и установите зависимости. Для облачных рекомендаций выполните настройку GigaChat ниже в этом же окне до запуска Uvicorn. Последняя команда запускает backend. Без настройки он использует локальную приоритизацию по правилам.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend\requirements.txt
.\.venv\Scripts\python.exe -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

Во втором терминале из папки с README запустите frontend:

```powershell
Set-Location frontend
npm.cmd ci
npm.cmd run dev
```

Откройте [интерфейс](http://127.0.0.1:5173), нажмите «Запустить проверку» и скачайте отчёт кнопкой «Скачать JSON». [Документация API](http://127.0.0.1:8000/docs) доступна после запуска backend. Vite проксирует запросы `/api/*` на порт 8000.

Переключатель «День / Ночь» находится в шапке. Браузер запоминает выбор темы.

Для первой установки зависимостей нужен интернет. Подготовьте ноутбук заранее: после установки локальная проверка, экспорт и режим правил работают без интернета. Оставьте оба окна PowerShell открытыми во время демонстрации.

## Публичное демо

`Dockerfile` собирает React и запускает FastAPI с интерфейсом и API по одному адресу. Сборка скачивает закреплённую версию Repair Desk. Для Render выберите **Web Service**, среду **Docker**, тариф **Free** и путь проверки состояния `/api/health`. Домен выдаёт хостинг.

Публичное демо готовит рекомендации по отчётам в режиме правил. Генерацию схем по описанию можно включить отдельно настройками сервера ниже. Для сравнения доступны два учебных ZIP из интерфейса. Сервер сопоставляет их как одну цель Demo Desk и принимает новые разрешённые учебные ZIP для отдельной проверки. История встроенных демонстрационных запусков общая для посетителей. На бесплатном Render она может сброситься после простоя, перезапуска или нового развёртывания.

## Проверка

### Сценарий защиты на 2–3 минуты

1. **0:00–0:30 — схема.** Откройте приложение. Выберите «Полная схема». Откройте параметры ноды «Условие» и покажите порог критичности.
2. **0:30–1:00 — результаты.** Нажмите «Запустить проверку». Покажите 15 находок, по пять SECRET, SCA и SAST. Выберите ноду, чтобы показать её журнал и результат. Отчёт появляется сразу после анализа.
3. **1:00–1:45 — решение и доставка.** Условие выбирает ветку «Да». В ней ИИ готовит рекомендации, а HTTP webhook получает итог. Нажмите ссылку «Находка N» в рекомендации и покажите строку «Webhook получен». Если облако недоступно, появится «Приоритизация по правилам» с теми же ссылками.
4. **1:45–2:30 — выборочный запуск и экспорт.** Нажмите «Только Maven SCA» и запустите сценарий. Покажите пять SCA-находок. Скачайте JSON.

### Ввод, ветвление и расписание

- Встроенный Repair Desk готов к запуску. Для другого разрешённого учебного проекта отметьте соответствующий флажок и выберите ZIP. `build.gradle.kts` должен быть в корне архива или в единственной верхней папке. Лимиты — 8 МБ на ZIP, 32 МБ после распаковки и 800 записей. Архивы не запускаются.
- Добавляйте ноды через «Тип ноды» и «Добавить ноду». Соединяйте за круглые контакты. Delete удаляет выбранную ноду или связь. В условии настройте минимум находок, минимальную критичность или регулярное выражение по пути. Нажмите на ноду, чтобы увидеть её результат и последовательность статусов.
- Для запуска по времени добавьте ноду «Расписание» и соедините её с «Учебным проектом». Выберите её, введите дату и время ISO 8601 с явным смещением, например `2026-11-21T14:30:00+03:00`, и нажмите «Запланировать». Выбирайте время не дальше часа. Планируется один одноразовый запуск. Запланированные и активные запуски сбрасываются при перезапуске backend. Завершённые остаются в истории.
- Редактор сохраняет ноды, связи, позиции и параметры в текущем браузере. Для переноса выберите «Экспорт схемы», скопируйте JSON на другой компьютер и выберите «Импорт схемы». После импорта проверьте дату в ноде расписания и при необходимости снова загрузите учебный ZIP. Файл схемы содержит только настройки графа. Отчёты, файлы проекта и ключи хранятся отдельно.
- По умолчанию webhook отправляется на демонстрационный приёмник того же backend. Для другого заранее согласованного получателя задайте `WORKFLOW_WEBHOOK_URL` в PowerShell backend до запуска. Клиентский граф не передаёт адрес. Поле `reportComplete` показывает, все ли анализаторы отчёта отработали. При частичном результате поле `failedAnalyzers` содержит идентификаторы анализаторов со сбоем. Ошибка доставки отмечается на ноде и сохраняет доступ к отчёту.

### Проверка в GitHub Actions

Вкладка **Actions → Security workflow** показывает прогоны на push и pull request. По умолчанию используется безопасный учебный образец `clean-training`. Ручной запуск с параметром `repair-desk` демонстрирует блокировку по CRITICAL. Оба сценария запускают тот же исполнитель графа с SECRET, SCA и SAST. Для использования в другом учебном пайплайне вызовите `python -m backend.ci clean-training` или `python -m backend.ci repair-desk` после установки зависимостей для тестов и подготовки набора.

В разделе **Artifacts** скачайте `security-report-<сценарий>`. Внутри лежат JSON с находками и `security-gate.json` с причиной и кодом выхода. Код 0 означает полный отчёт без CRITICAL, 1 означает наличие CRITICAL, 2 означает неполный отчёт или сбой.

Чтобы автоматически проверять код другого Kotlin/Gradle-репозитория, добавьте туда `.github/workflows/security.yml`:

```yaml
name: Project security
on: [push, pull_request]

permissions:
  contents: read

jobs:
  security:
    uses: CARDOMER/ai-security-workflow/.github/workflows/security-workflow.yml@public-demo
    with:
      project-directory: .
      scanner-ref: public-demo
```

Этот вызов требует, чтобы указанная версия workflow была опубликована и доступна вызывающему репозиторию. Для закрепления версии укажите один и тот же SHA коммита после `@` и в `scanner-ref`. Если `build.gradle.kts` лежит во вложенной папке, укажите путь к ней в `project-directory`. В репозитории сервиса аналогичный режим включается переменной GitHub Actions `SECURITY_PROJECT_DIRECTORY`. Ручные учебные прогоны остаются доступны.

В режиме проекта задача проверяет рабочую копию ревизии, которую GitHub Actions подготовил для события push или pull request, и публикует `security-report-project`. Задача читает исходники и конфигурацию без запуска Gradle и без ключа LLM. Для блокировки слияния добавьте статус задачи `security-gate` из первого прогона в обязательные проверки целевой ветки. В существующем пайплайне сборки можно сделать задачу сборки зависимой от этого вызова через `needs: security`.

### История и сравнение

В «Истории запусков» доступны последние 20 завершённых сценариев, включая запуски с ошибкой. «Открыть отчёт» показывает сохранённые находки и позволяет скачать JSON. Итоговые статусы нод отображаются в истории. Backend хранит отчёты и метаданные в локальном `workflow-history.sqlite3` в папке проекта. База не входит в переносимый ZIP. Исходники, загруженные архивы и токены не записываются в неё.

Кнопка «Сравнить демо в один клик» запускает три анализатора на обеих встроенных версиях Demo Desk, сохраняет два отчёта и сразу показывает различия. Готовить ZIP вручную для этого сценария не нужно.

### Загрузка учебного ZIP на Render

На сайте отметьте «Разрешённый учебный проект», выберите архив размером до 8 МБ и запустите проверку. Поддерживается Kotlin/Gradle-проект с `build.gradle.kts` в корне ZIP или единственной папки внутри. Backend читает файлы и выполняет статический анализ. В результате доступны находки, «Скачать JSON» и «Ссылка на отчёт». Отчёты по новым ZIP доступны по прямой ссылке и исключены из общего списка запусков. На бесплатном Render скачайте JSON, чтобы сохранить результат после перезапуска сервиса.

В инспекторе выполненной ноды вкладки «Вход» и «Выход» показывают данные текущего прогона. История сохраняет рекомендации вместе с отчётом. Чтобы webhook передавал ссылку на конкретный сохранённый отчёт, задайте `WORKFLOW_UI_URL` в окружении сервера, например `http://127.0.0.1:5173`. На Render используется `RENDER_EXTERNAL_URL`. Ссылка работает, пока соответствующий отчёт доступен в истории этой инсталляции.

### Библиотека и AI генерация схем

Откройте «Библиотека шаблонов», задайте название и описание и опубликуйте текущую схему. «Скопировать в редактор» создаёт редактируемую копию. Библиотека хранит последние 30 шаблонов в той же SQLite-базе, что и история. Файлы проекта, токены и результаты запусков не входят в формат шаблона.

В локальной версии с настроенным GigaChat или YandexGPT откройте «Создать схему по описанию» и введите задачу. Сервер проверит граф до подстановки в редактор. Проверьте параметры и запустите схему вручную. При ошибке LLM текущая схема остаётся в редакторе.

Для публичного демо с GigaChat задайте в окружении сервера `WORKFLOW_PUBLIC_LLM=1`, `AI_SUMMARY_PROVIDER=gigachat`, `AI_SUMMARY_MODEL=GigaChat-2-Max` и секрет `GIGACHAT_CREDENTIALS` со значением Authorization Key. Если сертификат НУЦ Минцифры отсутствует в системном хранилище доверия контейнера, добавьте PEM на сервер и укажите в `GIGACHAT_CA_FILE` путь к нему внутри контейнера. Текущая интеграция запрашивает токен с областью `GIGACHAT_API_PERS`.

После развёртывания посетители могут открыть «Создать схему по описанию» без входа и собственного ключа. Провайдер получает текст промпта с системной инструкцией. Общий лимит для всех посетителей составляет 5 попыток за минуту и 60 за сутки в пределах текущей базы сервиса.

### Уведомления Telegram

Для отдельного учебного чата задайте `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` в окружении локального backend и подключите ноду «Telegram» после отчёта, условия или AI-разбора. В чат передаются счётчики, максимальная критичность, признак полноты и доступная ссылка на отчёт.

Чтобы получать уведомления от публичного демо Render, задайте там переменные `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` и `WORKFLOW_PUBLIC_TELEGRAM=1`. Когда посетитель запускает проверку загруженного ZIP или вручную запускает Repair Desk, сервер отправляет JSON-отчёт, счётчики и ссылку в настроенный чат после сохранения отчёта. Ссылка строится из `RENDER_EXTERNAL_URL` или заданного `WORKFLOW_UI_URL` и должна использовать HTTPS. Сравнение Demo Desk в один клик работает без рассылки. Для публичных запусков действует общий лимит в 5 попыток за минуту и 60 за сутки в пределах текущей базы сервиса. JSON-отчёт доступен в интерфейсе и при ошибке Telegram. HTTP webhook продолжает работать как нода схемы.

Нажмите на название находки в текущем или сохранённом отчёте, чтобы открыть её карточку. Для SCA карточка показывает диапазон и исправленные версии, если они указаны в локальном справочнике Maven.

### Качество анализа

В разделе «Качество анализа» нажмите «Сверить с эталоном Repair Desk». Сервер заново запускает три анализатора и сверяет находки с `test-data/ground-truth/training-findings.json`. Для SECRET и SAST он сопоставляет категорию, путь, класс и начальную строку в пределах основного или альтернативного диапазона. Для SCA он сверяет путь, координаты с версией и один из идентификаторов advisory. Каждая эталонная запись сопоставляется с одной находкой. Срабатывания на безопасных контролях считаются отдельно. Эталон используется только для этой сверки и тестов.

Для демонстрации загрузите `demo/check-before.zip`, укажите имя цели `Demo Desk` и запустите полную схему. Повторите с `demo/check-after.zip`, тем же именем и теми же анализаторами. В истории выберите предыдущий и новый запуск. Результат на этой паре: 0 новых, 2 исчезнувшие и 1 сохранившаяся находка. Имя цели в двух версиях ZIP задаёт пользователь. Для Repair Desk цель определяется автоматически. Сравнение учитывает набор анализаторов, реально участвовавших в отчёте, и отклоняет неполный результат из-за сбоя анализатора. SECRET и SAST сопоставляются по пути, классу и строке. Перемещение строки может выглядеть как исчезновение одной находки и появление другой. Для SCA учитываются координаты и advisory ID.

## Необязательный ИИ-разбор

### GigaChat Freemium для учебной защиты

Создайте проект GigaChat API для физлиц в режиме Freemium. В настройках API нажмите «Получить ключ» и используйте значение Authorization Key. Подготовьте корневой сертификат НУЦ Минцифры в формате PEM по инструкции GigaChat. Путь ниже укажите к своему файлу. Если сертификат уже доверен в Windows, переменную пути можно пропустить.

```powershell
$env:AI_SUMMARY_PROVIDER = "gigachat"
$env:AI_SUMMARY_MODEL = "GigaChat-2-Max"
$env:GIGACHAT_CA_FILE = (Read-Host -Prompt "Путь к PEM (Enter, если сертификат уже доверен Windows)").Trim('"')
$key = Read-Host -Prompt "Authorization Key GigaChat" -AsSecureString
$env:GIGACHAT_CREDENTIALS = [System.Net.NetworkCredential]::new("", $key).Password
Remove-Variable key
.\.venv\Scripts\python.exe -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

Скопируйте ключ из Studio после появления приглашения, чтобы копирование команд не заменило его в буфере. Для настройки сертификата достаточно указать путь к PEM. Ключ и сертификат загружаются отдельно от ZIP. После настройки сделайте контрольный запуск на ноутбуке без VPN. По запросу рекомендаций сервер получает токен с областью `GIGACHAT_API_PERS` и передаёт модели только проверенные метаданные учебных находок. При ошибке сети, TLS или ответа включается приоритизация по правилам. Freemium предназначен для личного некоммерческого использования.

Для параллельной демонстрации запустите `.\check-gigachat.ps1 -Serve` в локальном PowerShell. В этом скрипте ввод ключа виден в консоли. Во втором PowerShell из папки с README задайте `$env:WORKFLOW_BACKEND_URL = 'http://127.0.0.1:8001'` и запустите `npm.cmd --prefix frontend run dev -- --port 5174`. Откройте [демонстрационный интерфейс](http://127.0.0.1:5174/), выберите «Полная схема» и запустите Repair Desk. При успешном ответе модели появится заголовок «Рекомендации GigaChat».

[Быстрый старт GigaChat](https://developers.sber.ru/docs/ru/gigachat/individuals-quickstart) · [Сертификаты](https://developers.sber.ru/docs/ru/gigachat/certificates) · [Тарифы для физлиц](https://developers.sber.ru/docs/ru/gigachat/tariffs/individual-tariffs)

### Yandex AI Studio как альтернативный провайдер

Для Yandex AI Studio используется YandexGPT Pro 5.1. Его Chat Completions API принимает JSON Schema и API-ключ сервисного аккаунта. Для обоих облачных вариантов метаданные отправляются выбранному внешнему провайдеру.

В Yandex Cloud получите ID каталога и API-ключ сервисного аккаунта с ролью `ai.languageModels.user`. В PowerShell 7, из которого запускается backend, задайте переменные и перезапустите Uvicorn.

```powershell
$env:AI_SUMMARY_PROVIDER = "yandex"
$env:AI_SUMMARY_MODEL = "yandexgpt-5.1"
$env:YANDEX_FOLDER_ID = Read-Host -Prompt "ID каталога Yandex Cloud"
$env:YANDEX_API_KEY = Read-Host -Prompt "API key Yandex Cloud" -MaskInput
```

На защите запустите полный сценарий на 15 находок, нажмите «Подготовить рекомендации» и откройте одну из ссылок «Находка N». Повторите для ветки SCA на 5 находок и скачайте JSON. Проверьте облачный вызов заранее на машине и сети защиты с выключенным VPN. При отсутствии ключа, сетевой ошибке или некорректном ответе появится «Приоритизация по правилам». Она сортирует текущие находки по критичности и предлагает до трёх действий. Чтобы заранее включить этот режим, задайте `$env:AI_SUMMARY_PROVIDER = "rules"` и перезапустите backend. Резервный режим работает при доступном локальном backend и отключённом интернете.

`POST /api/report/summary` принимает исходный JSON-отчёт с заголовком `X-Report-Signature` из ответа `POST /api/scan`. Сервер проверяет подпись и передаёт Yandex AI Studio только номера находок, категории, классы или advisory ID, критичность, относительные пути, строки и координаты зависимостей Repair Desk. Используются `store: false` и `x-data-logging-enabled: false`. Ключ остаётся в окружении backend и используется только в заголовке авторизации. Ответ содержит `mode: "llm"` или `mode: "rules"` с причиной перехода. Подпись действует в рамках текущего процесса backend. После перезапуска выполните проверку заново.

Перед отправкой метаданных реальных банковских отчётов в облако требуется согласовать передачу данных с банком, включая состав полей и условия хранения. Если все данные должны оставаться внутри контура, оцените локальную модель отдельно по поддержке JSON Schema, качеству русского текста и времени ответа на целевой машине. Локальная приоритизация по правилам уже доступна.

## Устройство MVP

- `POST /api/scan` проверяет `test-data/training-project` и возвращает единый массив `findings` по спецификации организаторов. Для SECRET и SAST отчёт содержит класс и строки находки, для SCA — координаты Maven, версию и один `advisoryId` в формате GHSA. Все находки содержат путь, критичность и описание.
- Для выборочного запуска передайте JSON, например `{"analyzers":["sca"]}`. Допустимые идентификаторы — `secret`, `sca` и `sast`. Запрос без тела запускает все три. Пустой список и неизвестный идентификатор возвращают HTTP 422.
- Secrets Scanner проверяет характерные объявления паролей, API-ключей и токенов, токены в конфигурации, встроенные значения по умолчанию и простую сборку токена из двух локальных литералов перед авторизацией. Описание использует один и тот же шаблон маски для любого значения.
- Добавление анализатора начинается с контракта `scan(root)` и регистрации в backend. React Flow передаёт граф в `POST /api/workflow/runs`. Сервер проверяет связи и исполняет граф в топологическом порядке. Интерфейс опрашивает состояние запуска и показывает серверные статусы и журнал переходов. API `POST /api/scan` и ручное получение рекомендаций доступны отдельно.
- Maven SCA читает строковые координаты в блоке `dependencies` корневого `build.gradle.kts`. Он поддерживает литералы, подстановки локальных переменных и значения из `gradle.properties`, прочитанные через `providers.gradleProperty`. Для объявленной зависимости приоритет имеют записи `gradle.lockfile`. Если зафиксировано несколько версий, каждая проверяется отдельно. Gradle и Repair Desk не запускаются.
- Анализ использует числовые диапазоны локального `test-data/vulnerability-database/vulnerabilities.json`. Для прямых вызовов `libs.*` читает каталог `gradle/libs.versions.toml` со строковыми версиями и `version.ref`. Вычисляемые объявления, bundles, сложные ограничения версий, транзитивные зависимости и версии с квалификаторами за пределами этого разбора.
- Kotlin SAST ищет подстановку HTTP-параметра в SQL, безусловное разрешение имени хоста, CORS с произвольным источником и учётными данными, перекрытие защищённого маршрута публичным правилом и запрос объекта без ограничения владельца.
- SAST использует ограниченные шаблоны Kotlin и Spring, простые прямые вызовы между контроллером и репозиторием и признаки клиентских данных в SQL. Он не выполняет анализ типов или полный анализ потока данных. Обёртки, алиасы, сложные SQL-условия и нестандартные схемы авторизации могут потребовать дополнительных правил.
- Эталон читается только тестами. Учебный снимок даёт пять SECRET, пять SCA и пять SAST.
